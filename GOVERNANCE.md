# Governance

This is a maintainer-led project. Maintainers review proposals, decide what merges,
choose releases and control publishing/deployment. Contributors can propose issues
and pull requests; contribution does not grant production or repository-admin access.

Open an issue before a large change. Keep fixes bounded, preserve fail-closed risk
screening, and provide reproducible tests. Contributions require Developer Certificate
of Origin (DCO) sign-off with `git commit -s`; there is no CLA. Maintainers may ask for
revision or decline a proposal. See [CONTRIBUTING.md](CONTRIBUTING.md).

Public releases are separately reviewed snapshots. Private development history,
credentials, account state, user data, internal working instructions and deployment
identities must not be copied into releases. A new commit on main does not remove
other advertised refs. Maintainers audit the actual release refs before publication.

Questions and escalation: contact@iscalelabs.com. Security reports are private as
specified in [SECURITY.md](SECURITY.md).
